# 声の設定

メニュー → 声の設定で音声サービスを選び、「声を試す」で確認する。トークのスピーカーをONにすると返事を読み上げる。設定は同じログインで使う端末に共通。さくらの無料枠を使い切ったというユーザー申告を受け、現在の初期選択はTTS QUEST。

- TTS QUEST: 非公式WEB版VOICEVOXの公開API。ずんだもんノーマル（話者3）。APIキー不要の利用方法を採用。
- さくら: `ZUNDAMON_SAKURA_AI_API_KEY` がこの独立サーバーに設定されていれば選択できる。YUIの秘密は自動流用しない。未設定は選択不可。
- サービス変更だけでは音声生成を行わない。試聴・読み上げで文章を選択したサービスへ送る。
- 利用制限時の自動切替、月替わりの自動復帰、プラン変更はしない。さくらの残り無料回数をアプリが取得する機能はない。さくら選択時の料金は契約中のプランに従う。
- 設定は `data/voice-connection/` に所有者IDごとに保存（Git対象外、APIキーなし）。

## 実装境界

TTS QUESTへは文章をPOSTで送信する。返却されたURLはHTTPS・audio1〜9.tts.quest・所定のパスだけを許可し、リダイレクトを拒否。応答サイズ、生成待ち時間、音声形式を検査する。生成依頼を直列化し、retryAfter中は新しい依頼を送信しない。キャンセルした待機中の文章を送らない。制限時は文字の会話を継続できる。

今回のプレイヤーはWAV生成完了後に再生する。TTS QUESTのMP3ストリーミングは未接続で、最初の音が出るまでの短縮は後続の検証対象。ライブチャットと文字起こしも、この変更だけでは有効にならない。

## 連続会話での遅延・制限への対応（2026-09-11）

ユーザーが、文字表示後の音声待ちと2往復程度での利用制限を報告。通常トークでもストリーミング用キューを使い、句点・改行と60/120文字の境界で多数の合成依頼を送っていたことを確認。完成済みの通常返信は240 UTF-16単位以内なら1回にまとめ、長文のみ上限で分割するよう変更。絵文字の分断を避け、先読み送信も廃止した。上限エラー後は後続部分を送信しない。

関連Webテスト12件・型検査・接続ビルド成功。これは呼び出し回数の修正であり、TTS QUEST無料APIの待ち時間・制限解除・ストリーミング再生の実現ではない。実サービスの制限中に再試行を繰り返す試験は行っていない。

## 従量課金移行後の比較

さくらの専用キー接続と実音声生成を確認。3回とも成功（WAV取得完了まで0.497〜2.419秒）。TTS QUESTは1回成功後、2回目で利用制限。選択は自動変更していない。条件・限界は 音声API比較（開発時の検証記録） を参照。
