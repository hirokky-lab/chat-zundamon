# 初期設定

AIに手伝ってもらう場合は [AI向けセットアップガイド](setup-guide.md) から進めてください。

GitHubから設置する人が、自分のAI・保存先・音声・Google接続情報を登録するためのローカル画面。作者のサーバーやキーには接続しない。公開配布のライセンス確認や空のクラウド環境での通し検証は別工程。

## 始め方

Node.jsとpnpmを用意して、このリポジトリで `pnpm install` の後に `pnpm setup:app` を実行する。表示されたURLを、同じコンピューターのブラウザーで開く。

`pnpm start:connected` でも、`.env.connection.local` が存在しなければ初期設定を案内する。設定済みなら通常起動し、別端末へ初期設定を繰り返し表示しない。画面だけを確認する場合は `pnpm setup:preview`。プレビューでは接続・保存をサーバー側でも拒否する。

初期設定は127.0.0.1だけで待ち受ける。クラウドサーバーへ設置する場合は、ローカル転送などで管理者がアクセスする。初期設定のポートをインターネットに公開しない。公開アプリのログイン前に秘密設定画面を出す方式ではない。

## 順番

1. **AI**：OpenAI専用キー。接続確認では固定モデルのメタデータを取得し、文章を生成しない。会話生成・課金残高までは検証しない。現行対応はOpenAIのみ。
2. **保存・同期**：専用SupabaseのURL、公開用キー、サーバー用キー、許可するメールアドレス、アプリのHTTPS入口。接続確認ではAuth設定と基本3テーブルへのアクセスを確認する。個人データを取得しない（limit=0）。現在は標準Supabaseドメインのみ対応、D1やカスタムDBホストは未対応。
3. **声**：あとで設定／さくら／TTS QUEST。さくらのキーは保存のみで、音声生成しない。新しいユーザーの初期選択に反映し、既存ユーザーの選択は優先する。「あとで」は音声キーなしで開始し、通常どおり起動時の読み上げはOFF。試聴はログイン後の声の設定で行う。
4. **Google**：あとで設定、または自分のOAuthクライアントを登録。暗号鍵は設置先で新規生成する。カレンダー・Drive・Gmailの機能を準備するが、アカウントの接続やアクセス許可はログイン後に別途行う。登録しただけで読み書きしない。
5. **確認・保存**：接続確認した内容だけを保存。入力変更後は再確認が必要。保存後はCtrl+Cで初期設定を終了し、`pnpm build:connected` → `pnpm start:connected` を実行する。ログイン後は既存の名前入力へ進む。

## 保存先とログインの事前準備

初期設定画面はDBやGoogle Cloudのアカウントを作成しない。

- [保存先とログインの準備](service-setup.md) に沿って専用プロジェクトを用意し、`supabase/migrations` を順番に適用する。全マイグレーション・RLS・写真用ストレージの準備が必要。基本3テーブルの確認成功だけで完了としない。
- Supabase AuthのGoogleプロバイダーを設定する。Supabaseが表示するAuthコールバックURLをGoogle側へ登録する。
- Supabase AuthのSite URL・許可する戻り先を、自分のアプリのHTTPS入口に合わせる。
- 本アプリの4393番へのHTTPS入口を準備する。公開入口・サーバーは利用者自身のもの。現在の構成は常時稼働するNodeサーバーと永続ディスクを必要とする。
- キャラクターやLive2D素材については [キャラクター素材](character-art.md) と [AI接続](ai-connection.md) の配布前確認も参照する。除外された素材をGit cloneだけで取得できるとは限らない。

## Google連携の事前準備

[Google連携の準備](service-setup.md) に沿ってAPI、同意画面、ウェブアプリ用OAuthクライアントを準備する。初期設定に表示するコールバックはアプリのURL＋`/api/google-calendar-tasks/callback`。これはSupabase Authのコールバックとは別。利用者への許可要求や操作ごとの外部変更確認は既存のアプリ側で行う。

## 保存と保護

接続情報は設置先の `.env.connection.local` へ権限600で保存。ブラウザーの永続保存・会話DB・応答・ログにキーを保存しない。Git除外済み。既存ファイルやシンボリックリンクは上書きせず、初期設定から既存個人データを移行しない。設定済み環境のAI・声・Google連携は既存アプリの画面から管理する。DBの切替・移行UIは未実装。

初期設定の入口は起動ごとのランダムURL、Host確認、同一OriginのJSON送信に限定。外部APIはリダイレクト禁止・タイムアウト付き。保存時も検証済みの入力と一致することを確認。サーバー自体を管理できる人から環境ファイルを隠す仕組みではない。

## 検証の境界

2026-09-11、空のローカルDBへ44件のマイグレーションを適用し、17ファイル・499項目のSQLテストが成功。検証記録（開発時の検証記録）。クラウドの新規ログインと実端末同期の通し確認は別途必要。

自動テストは架空キーと模擬応答を使用。既存の本人用環境は変更しない。ブラウザーのプレビューでステップ遷移と390px幅を確認。新規プロジェクト作成からログイン・会話・同期・音声までの実環境通し検証は未実施。

### VRMのサーバー保存（任意）

VRMは端末内保存だけでも利用できます。端末をまたいで使う場合は、本人用Supabaseのマイグレーション `202609120002_vrm_storage.sql` まで適用すると、キャラクター設定でサーバー保存を選べます。既存の認証・接続設定を使うため、追加のパスワード入力は不要です。

保存先は非公開の `zundamon-vrm`、上限50MB/ファイルです。Supabaseの無料枠は既存ファイルや転送量と共有するため、管理画面のUsageを確認してください。有料プランへ自動変更する機能はありません。モデル本体はGitHubに含めず、各利用者が利用条件を確認して追加します。アプリをMac以外へ移設する作業とは別です。

## 任意: Codexからコードを調査する

既にCodexへログイン済みのMacでは、[Codexへの作業依頼](codex.md)を有効にできます。本人のCodex設定に従って調査・編集・テストを依頼し、進捗や確認事項をアプリで受け取れます。通常の会話用AI設定とは別の接続で、未設定でもアプリを利用できます。
