# AI接続と自分用の起動

## アプリでの設定

メニュー → AI接続 → APIキーを取得する → キーを貼り付ける → 確認して保存する。

接続確認は短いResponses API呼び出しで、実際に採用モデルが利用できるか確認する。ChatGPT契約とAPI料金は別。失敗したキーでは現在の設定を上書きしない。保存後は次の会話、写真解析、記憶抽出、Googleの内容理解から新しいキーを使う。実行中の通信は開始時のキーを使う。

入力したキーは保存後に入力欄から消え、状態取得APIはキーを返さない。「登録済み」と「接続確認成功」は区別する。Google連携の認証や音声サーバーの設定はこの画面に含まない。

解除すると、その所有者のAI呼び出しを停止する。サーバー環境変数の古いキーへ自動復帰しない。会話や記憶は削除しない。OpenAI側のキー失効はOpenAI管理画面で行う。

## 保存方式と境界

現在は本人用の常駐Nodeサーバー。許可メールアドレスをSupabase Authで検証し、保存データは認証ユーザーIDで分離する。AES-256-GCMで暗号化し、ユーザーIDをAADに使う。

- 保存先: リポジトリの `data/ai-connection/`（Git除外）。キー登録・解除時に初めて作成。
- 暗号化ファイルと暗号鍵 `master.key` は別ファイル。ディレクトリ700、作成ファイル600。
- 端末間の共有は、同じサーバー・同じログインを使うことで実現。キーはブラウザの永続保存やSupabaseの会話データに入れない。
- 既存の専用環境変数 `ZUNDAMON_OPENAI_API_KEY` は初期設定としてのみ利用。アプリで登録・解除した設定が優先する。
- サーバーのファイル全体にアクセスできる人から秘密を守る仕組みではない。公開用の複数利用者サービス、複数サーバー構成、永続ディスクのないホスティングにはこの保存実装をそのまま使わない。
- サーバーを移す場合、暗号化ファイルと暗号鍵を安全な経路で移すか、新環境で再登録する。GitHub・設定プリセット・会話バックアップへ含めない。

## 自分用の接続環境を作る

1. `pnpm setup:app` で [初期設定](initial-setup.md) を開く。従来の `.env.example` を参考にした手動設定も利用できる。実値をREADMEやコミットに書かない。
2. 専用Supabaseプロジェクトを作り、`supabase/migrations` のマイグレーションを順に適用する。AuthのGoogleプロバイダーとアプリの戻り先を設定する。詳細は [Supabase準備](service-setup.md)。
3. `ZUNDAMON_SUPABASE_URL`、`ZUNDAMON_SUPABASE_PUBLISHABLE_KEY`、`ZUNDAMON_SUPABASE_SERVICE_ROLE_KEY`、`ZUNDAMON_ALLOWED_EMAIL`、HTTPSの `ZUNDAMON_ALLOWED_ORIGIN` を専用値で設定する。
4. `pnpm build:connected` → `pnpm start:connected`。フロントは127.0.0.1:4393、APIは127.0.0.1:4384。4393を本人用HTTPS入口へつなぐ。端末間の認証・同期には同じ入口を使う。
5. Googleでログインし、メニューのAI接続から自分のAPIキーを登録する。OpenAIキーを事前に環境変数へ書く必要はない。
6. カレンダー・Drive・Gmailは [Google連携](google-connections.md) を見て、各自のGoogleプロジェクトと利用許可で接続する。

現在のMac上の常駐サーバーではMacの稼働が必要。Cloudflare D1への保存切替と一般向け配布のクリーン環境検証は未完了。音声の選択画面と設置者向け初期設定は実装済み。

## GitHub公開前に必要なこと

- 作者の環境変数、`data/`、個人の写真・会話・バックアップを含めない。
- キャラクター、モデル、背景、Live2D SDK、音声、継承コードの利用条件と再配布可否を個別に確認する。
- 再配布しない素材は取得方法と配置先を案内する。
- 空の環境からセットアップ手順を再現し、公開用サンプルだけで検証する。

AITuberKitの設定導線を参考にした独自実装。AITuberKitのコードは移植していない。調査は AITuberKit調査（開発時の検証記録）。
