# AIと一緒に導入するためのガイド

この文書は、利用者から導入を頼まれたAI向けの進め方です。人が直接読んでも使えます。実際の設定項目とコマンドは [初期設定](initial-setup.md) を正本とし、この文書だけを根拠に未実装機能を案内しないでください。

## 1. 現状を確認する

まずREADME、AGENTS.md、初期設定ガイド、package.jsonを読む。利用者がどこまで済ませているかは、読み取りで確認できる範囲を先に調べる。

- 作業対象がこのリポジトリであること、作業中の変更があるかを確認する。他のプロジェクトを編集しない。
- Node.jsとpnpmの有無・バージョンを確認する。pnpmの指定はpackage.jsonのpackageManagerに従う。既存の実行環境を一括更新しない。
- `.env.connection.local` は存在・権限・必要項目の有無だけを調べる。ファイル全体や値を出力しない。設定の存在を、接続成功とは扱わない。
- 接続サーバーや初期設定画面がすでに起動しているかを確認する。起動済みのポートや別アプリを無断で停止しない。
- 未設定なら設置先を確認する。利用者自身のPCかサーバーを使い、作者の私用URL・Supabaseプロジェクト・APIキーを例からコピーしない。

確認できた状態を「済み・未設定・未確認」で短く伝える。すでに会話・同期が動いているなら新規導入を繰り返さず、依頼された設定だけを扱う。

## 2. 必要な準備だけ進める

新規導入は依存関係を `pnpm install --frozen-lockfile` で準備する。失敗時にロックファイルを削除したり、別バージョンで作り直したりせず、原因を確認する。

まず動く画面を見たいだけなら `pnpm setup:preview` を使う。実接続・保存は行われないと明示する。

実導入では [保存先とログインの準備](service-setup.md) と [初期設定](initial-setup.md) に従い、DBマイグレーション、Googleログイン、HTTPS入口を準備する。新しい専用DBか、既存データのあるDBかを区別する。既存DBをリセットしない。DBや課金契約の変更は、今回の依頼で承認された範囲を確認して進める。

現在の接続モードはOpenAI・Supabase、常時稼働するNodeサーバーと永続ディスクを前提とする。Cloudflare D1や他のAI提供元を、設定変更だけで使えると案内しない。Git cloneだけでLive2D素材もそろうとは限らないため、[素材の案内](character-art.md) も読む。

## 3. 初期設定画面へ案内する

`pnpm setup:app` を起動し、その回に表示されたURLを開く。以前のランダムURLを使い回さない。初期設定は設置先の127.0.0.1に限定される。別のPCやスマートフォンからそのまま開けるURLとは説明しない。遠隔サーバーでは管理者用のローカル転送を使う。

利用者には、AI → 保存・同期 → 声 → Google → 確認の順で案内する。キーは本人が画面へ直接入力する。AIがキーを扱う必要がある場合も、値がチャット・ツール出力・画像・Gitへ出ない方法を使い、ブラウザー画面の読み取りで秘密値を拾わない。

声とGoogle連携は後回しにできる。Googleログインと、カレンダー・Drive・Gmailへの利用許可は別であり、コールバックURLも混同しない。Google側の準備は [Google連携の準備](service-setup.md) を参照する。

設定済みと表示されたら、ファイルを削除して回避しない。AI接続・声・Google連携は既存のアプリ画面で変更する。DB切替・個人データ移行のUIは未実装なので、必要なら別の作業として具体化する。

## 4. 起動して確認する

保存後に初期設定を終了し、`pnpm build:connected`、`pnpm start:connected` の順で進める。起動済みなら重複起動せず、設定変更の反映に再起動が必要か確認する。

利用者自身のHTTPS入口で次を確認する。実APIを使う確認は短い内容にし、音声を勝手に連続再生しない。

| 確認項目 | 完了と判断できる状態 |
| --- | --- |
| ログイン | 許可した本人でログインし、アプリへ戻れる |
| プロフィール | 新規なら名前を登録し、再表示して確認できる |
| 会話 | 自分のAI接続で返事が来る。定型の表示確認ではない |
| 保存 | 再読み込みしても送った内容が残る |
| 同期 | 別端末で同じアカウントに入り、同じ内容を確認できる |
| 記憶 | 覚えた内容を確認・修正・削除できる範囲を実際に確かめる |
| 音声（任意） | 試聴が実際に聞こえる。利用者の確認も得る |
| Google（任意） | 利用許可後に接続先を確認。書き込み試験は対象と操作の承認がある場合だけ |

初期設定の接続確認は限定的。AIのモデル情報取得は会話生成の成功を保証せず、基本テーブルへの接続は全DB機能の準備完了を保証しない。実端末で確認できない項目は「未確認」として残す。

## 5. つまずいたとき

| 症状 | 最初に確認すること |
| --- | --- |
| 初期設定リンクが開かない | プロセスが動いているか、今回表示されたURLか、設置先と同じ端末か |
| 設定済みと表示される | 既存設定を維持し、アプリ側の設定画面を案内する |
| OpenAIの接続確認に失敗 | キーの提供元・権限・利用できるモデル。値は出力しない |
| 新しい保存先を作れない | 無料枠などの上限。既存プロジェクトの停止・削除・課金変更は勝手に行わない |
| DB接続確認に失敗 | プロジェクトURL、キーの種類、マイグレーション適用状態 |
| Googleログインから戻れない | Supabase Authのプロバイダー、Site URL、戻り先。サービス連携用URIと区別 |
| 声が出ない・利用制限 | 選択サービスと試聴結果。制限中に自動再試行や有料サービス切替をしない |
| 別端末と同期しない | 同じアプリURL・同じログインか、ローカル表示確認モードではないか |

ログを調べる場合は秘密値・認証トークン・個人の会話を除外する。認証失敗を直すために認証や所有者分離を無効にしない。

## 利用者への伝え方

自分で確認・修正できる作業は先に進める。本人のログイン、認証コード、契約選択などで操作を引き継ぐ場合は、画面名と次の一操作を伝える。認証コードをチャットへ貼るよう求めない。すでにある承認は引き継ぎ、同じ確認を繰り返さない。

終了時には「使える状態になった機能」「後回しにした機能」「未確認の項目」を短く伝える。GitHub公開・クラウド配備・課金開始・個人データ移行は、導入手順を書いたことだけで実施済みとしない。この開発版の新規環境での通し検証は、現時点で完了していない。
