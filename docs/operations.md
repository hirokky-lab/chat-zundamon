# Chatずんだもんの起動・バックアップ・復旧

対象は設定済みの個人用環境。新しく設置する場合は [AI向けセットアップガイド](setup-guide.md) → [初期設定](initial-setup.md) を使う。既存設定を削除して初期設定からやり直さない。

## 普段の起動と更新

リポジトリで `pnpm install --frozen-lockfile`、`pnpm build:connected`、`pnpm start:connected` の順に実行する。設定済みなら初期設定画面へ戻らず起動する。Macを起動しただけで自動起動する仕組みは今回追加していない。

通常はHTTPが127.0.0.1:4393、APIが127.0.0.1:4384。スマホは設定済みのHTTPS入口を使う。Macの稼働・アプリのプロセス・Tailscaleの接続が必要。Macのスリープ中にも利用できるクラウド常駐サービスではない。

確認は `curl -f http://127.0.0.1:4393/api/healthz`。正常時は `{"ok":true}`。これはサーバーの生存確認であり、OpenAIの生成・音声・外部連携すべての正常性は保証しない。

起動しない場合は、起動したターミナルのエラーとポート使用状況を確認する。同じポートで二重起動しない。自分が起動したプロセスをCtrl+Cで終了し、設定を保持したまま再起動する。スマホだけ開けない場合は、先にMacのローカルURLで正常応答するかを確認する。

普段のアプリを止めずに起動を試すには次を使う。

```sh
ZUNDAMON_API_PORT=4484 ZUNDAMON_HTTP_PORT=4493 pnpm start:connected
```

この起動確認も既存の保存先を参照するため、会話や保存の試験には使わない。終了時はこの確認用プロセスだけを止める。

## バックアップを作る

会話や設定変更を一度止めた状態で、リポジトリから `pnpm backup:local` を実行する。DBには読み取りだけを行う。完了すると `data/backups/chat-zundamon-日時.enc` と検証結果の `.enc.json` が作られる。作成ごとに別名で保存し、既存のバックアップを上書きしない。

暗号鍵は `~/.local/share/chat-zundamon/backup.key`。鍵と接続情報はチャットやGitへ貼らない。バックアップと鍵の両方がないと復旧できない。

2026-09-13、暗号化バックアップと初版ソースを本人のGoogleドライブへ保存し、鍵は本人指定のDropbox「Chatずんだもん_復旧用（非共有）」へ分けて保存した。どちらも非共有を確認済み。Driveのダウンロード内容は元ファイルとSHA-256が一致し、Dropboxはアップロード済みを確認。両方のコピーから別フォルダへ復元し、接続設定の一致を確認した。

これは今回の手動退避。今後のバックアップが自動でDriveへ送られる設定はまだない。大きな変更の後は新しいバックアップを作り、同じ鍵を保持したままDriveへ追加する。古い鍵を失くすと、古いバックアップは復号できなくなる。

保存範囲:

- 手元の接続設定、ローカルデータ、BGM、Live2D素材。
- クラウドのプロフィール、記憶、写真参照を除いた会話スナップショット、利用記録。

保存対象外:

- Supabase Auth、クラウド内のGoogleトークン、写真・VRMのStorage実体、削除台帳、その他のクラウドテーブル。
- ブラウザの端末内設定や、端末内だけにある未同期データ。
- ソースコードと依存パッケージ。ソースは別のリリース保存から戻す。

これは完全なDBバックアップではない。取得はページ単位の読み取りで、DB全体の同一時点スナップショットではない。クラウド全体の復旧には、Supabase側のDB・Auth・Storageのバックアップが別途必要。

## まず別フォルダへ復元する

```sh
pnpm restore:local data/backups/対象ファイル.enc data/backups/recovered-check
```

展開先は存在しない新規フォルダにする。鍵が別の場所にある場合は第3引数で鍵ファイルのパスを指定できる。既存フォルダへの上書き、改ざん・破損したバックアップ、リンクを含むアーカイブは拒否する。成功後、展開先の設定・データ・素材を確認する。この操作は稼働中のアプリやクラウドDBを書き換えない。

展開内容には秘密設定が含まれる。本人用フォルダのまま扱い、画面共有・公開フォルダ・Gitに移さない。不要になった復元確認用コピーは削除する。

Mac側の障害なら、保存したソースを別の作業フォルダへ戻し、必要なローカル設定と素材を展開先から戻してビルドする。まず上記の別ポートで起動を確認し、通常起動を切り替える。設定のクラウド接続先を変えなければクラウドの会話を改めて上書きする必要はない。

`cloud-non-photo.json` はさらに暗号化された非写真データであり、そのままSQLとして投入しない。クラウドデータの復旧が必要なときは、対象所有者・バックアップ日時・削除台帳との整合を確認し、既存の復元処理を使って別環境で検証してから判断する。過去に削除した情報を復活させない。今回、稼働中のクラウドDBへの復元は実施していない。
